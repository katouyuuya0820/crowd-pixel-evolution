# crowd-pixel-evolution

複数人がブラウザから参加する、対話型進化計算（Interactive Evolutionary Computation）のゲーム。
Picbreeder のように、並んだ画像からお題に一番近いものを選び続けると、砂嵐（完全な乱数）からドット絵が育っていく。

- 画像はドット絵そのもの（16×16 が既定）。第0世代は全画素がランダム
- 参加者は 3×3 に並んだ 9 枚から 1 枚をクリックで選ぶ（各自が別の組を見る）
- 一定数の選択が集まると、遺伝的アルゴリズムで次の世代へ
- 選択の結果を画素ごとに集計し、「どの位置にどの色が好まれるか」を次の世代づくりに使う

## 動かし方

[uv](https://docs.astral.sh/uv/) が必要。

```
uv sync
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Windows なら `run.bat` でも起動できる。

| 画面 | URL | 内容 |
|---|---|---|
| 参加 | `http://<サーバーのIP>:8000/` | お題と 9 枚の画像。クリック、または矢印キー＋Enter で選ぶ。右上にみんなの選択数と世代 |
| 管理 | `http://localhost:8000/server` | お題の入力、世代の進み、現在の集団、みんなの好み、参加用 URL と QR コード、リセット。サーバーの PC からのみ開ける |
| リザルト | `http://<サーバーのIP>:8000/result` | 一定世代ごとのベストと上位の移り変わり |
| ベスト | `http://<サーバーのIP>:8000/best` | いまの集団で評価が一番高い画像だけ（お題は出さない）。右上に選択数と世代 |

- 参加者の端末からサーバーの 8000 番へ届く必要がある（ファイアウォールの受信許可など）
- 管理画面を別の PC から開きたい時は、環境変数 `HIEC_ADMIN_OPEN=1` で起動する
- 記録は `data/<セッション>/` に保存され、再起動しても続きから始まる（`HIEC_DATA` で場所を変えられる）

## 色のモード

管理画面のリセットで選ぶ。どのパレットも 0 番が白。

| モード | 色 | 向いているお題 |
|---|---|---|
| `color8` | ファミコン風の 8 色（白・黒・赤・肌・茶・青・黄・緑） | キャラクターなどのドット絵 |
| `gray4` | 2 ビットのグレースケール（4 階調） | 文字・記号 |
| `mono2` | 1 ビットの白黒 | 文字・記号 |

解像度（8〜32）、集団の数、1 回に並べる枚数（4・6・9）、次の世代までの選択数も変えられる。

## しくみ

### 選択と適応度
- 1 回の選択で、選ばれた 1 枚が並んでいた残りすべてに勝ったと数える
- 適応度は平滑化した勝率 (勝ち+1)/(比較+2)
- 並べる組は、比較の少ない個体を優先して選ぶ。世代が進む前に出した組への選択は捨てる

### 次の世代（`app/ga.py`, `app/pixel.py`）
- 上位 2 体はそのまま残す（エリート）
- 残りは、トーナメント（5 体）で選んだ親から作る
  - 交叉（70%）：もう 1 体の親の長方形の領域を、同じ位置に貼り込む
  - 突然変異：
    - 0.5% の画素の色を変える
    - 15% で、領域の画素を周り 3×3 の多数派の色に合わせる
    - 30% で、小さな長方形を 1 色で塗る
    - 30% で、太さ 1〜2 画素・長さ 3〜8 歩の筆で線を引く（白なら消す）

### みんなの好み（`app/model.py`）
選択のたびに、各画素について次を数える。
- 提示：並んだ画像のその位置の色（偶然選ばれる期待値 1/k を足す）
- 選択：選ばれた画像のその位置の色（1 を足す）

数えるときにぼかしフィルターをかけ、上下左右に 0.5、斜めに 0.25 だけ同じ色として配る（線の位置の小さなずれを吸収する）。

選ばれやすさ = (選択 + 2) / (提示 + 2) で、1 なら偶然と同じ。これを確率にするとき、
- 2 乗して差を強める
- 全画素を合計した色ごとの選ばれやすさを 3 乗して掛ける（お題に合わない色は、集計が増えるほどだんだん出にくくなる）
- どの色でも差が無い画素は、白を少しだけ出しやすくする
- 10% はランダム（その半分は全体の色の割合に沿う）

子を作るとき、画素の色を変えるならこの確率で色を選ぶ。さらに数画素で「引いた色の方が出やすければ直す」（すでに良い画素は壊さない）。管理画面には、各画素で一番出やすい色を並べた画像を表示する。

## 自動投票での目安

`scripts/sim_votes.py` は、見本に一番近い画像を 8 割の確率で選ぶ自動の参加者を動かす。
同じ条件（16×16、9 枚から選ぶ、3 回の平均）で、ベストの画像と見本の画素の一致率は次のとおり。

| 見本 | モード | 250 回 | 500 回 | 1000 回 | 2000 回 |
|---|---|---|---|---|---|
| ハート | `color8` | 59% | 75% | 85% | 88% |
| 数字の 3 | `gray4` | 74% | 86% | 92% | 95% |
| 数字の 3 | `mono2` | 86% | 90% | 95% | 96% |

```
uv run python scripts/sim_votes.py --clients 8 --votes 100 --target heart
```

人の選択は見本どおりではないので、実際にはこれより時間がかかる。

## 開発

```
uv run pytest
```

| ファイル | 内容 |
|---|---|
| `app/main.py` | FastAPI のルーティング、WebSocket（選択数・世代・お題の即時反映）、管理 API |
| `app/state.py` | ゲームの状態、選択の受け付け、保存と再開 |
| `app/ga.py` | 集団、並べる組の選び方、次の世代 |
| `app/pixel.py` | ドット絵の遺伝子、交叉と突然変異、パレット |
| `app/model.py` | 画素ごとの色の好みの集計 |
| `static/` | 参加・管理・リザルトの画面（ビルド不要の HTML/JS） |
